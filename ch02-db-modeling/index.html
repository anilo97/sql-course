AI 홈 재활 서비스 데이터베이스 모델링 실습

현실의 재활 의료 업무를 분석해 논리적 데이터 표(Table)와 기본 키(PK)를 설계하고, MySQL Workbench에서 EER 다이어그램으로 구축하는 5단계 실습 워크시트입니다.

STEP 01

업무 분석: 서비스 시나리오 및 관리 대상 파악

약 5분

모델링의 첫 번째 단계는 서비스 시나리오를 읽고 고정적인 기준 정보(마스터 테이블)와 반복적으로 누적되는 행위 데이터(로그 테이블)를 구분하는 것입니다.

[서비스 시나리오] AI 홈 재활 운동 관리 플랫폼
  • 1) 환자 등록: 병원에서 퇴원 후 재택 재활이 필요한 환자가 가입하며, 이름, 생년월일, 성별, 주요 재활 부위(어깨, 무릎, 허리 등)를 관리합니다.
  • 2) 재활 운동 처방/종목: 물리치료사가 배정할 수 있는 표준 운동 종목으로 운동명, 타겟 부위, 난이도(초급·중급·고급) 정보를 관리합니다.
  • 3) 운동 수행 기록 측정: 환자가 집에서 스마트폰 카메라로 운동을 수행할 때마다 수행 일시, AI가 측정한 평균 관절 가동범위(ROM 각도), 통증 점수(1~10점)가 누적 저장됩니다.
도출된 3개 핵심 개체(테이블) 식별 체크 및 분리 이유 메모
STEP 02

논리적 표(Table) 설계

약 10분
열 이름 규칙: 띄어쓰기 없이 영문 소문자와 언더바(_) 사용을 권장합니다. (예: patient_id, birth_date)
기본 키(PK) 원칙: 테이블의 각 행을 유일하게 식별하는 열에 체크하세요. (중복 불가 및 빈칸(NULL) 불가)
STEP 03

예시 데이터(Row) 입력 및 검증

약 5분

STEP 02에서 작성한 열 이름과 데이터 형식, [PK] 표시가 아래 표 머리글에 실시간으로 동기화됩니다. 각 테이블별로 2개 이상의 예시 데이터(Row)를 직접 입력하여 기본 키 중복 여부와 구조의 무결성을 검증하세요.

STEP 04

MySQL Workbench EER 다이어그램 실습

약 15분

논리적으로 설계한 3개의 표를 MySQL Workbench 모델링 툴에 옮겨 물리 데이터 타입과 1:N 관계선(외래 키)을 직접 구축합니다.

논리 데이터 형식 → MySQL 물리 데이터 타입 매핑 가이드
논리 형식 MySQL 물리 타입 적용 대상 열 예시
문자 VARCHAR(길이) / CHAR(1) patient_id VARCHAR(20), name VARCHAR(30), gender CHAR(1)
숫자 INT (정수) / FLOAT (실수) log_id INT(PK, NN, AI), pain_score INT, avg_rom FLOAT
날짜 DATE / DATETIME birth_date DATE (연-월-일), performed_at DATETIME (일시)
MySQL Workbench EER 다이어그램 구축 순서 체크리스트 0 / 4 완료
